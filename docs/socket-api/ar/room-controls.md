# التحكم بالغرف: صلاحيات محلية وتحديثات عند التغيير

الدخول للمسجلين يبقى عبر JWT موثق ثم نجاح `authorize-join` وقراءة `/policy` وفحص `permissions.entry_error`. لم يتغير تجديد توكن Socket أو مؤقت انتهائه، ولا يفصل دخول جهاز آخر الجلسة الحالية. لا يوجد عقد توكن غرفة جديد أو دخول ضيوف مجهولين.

يحفظ Node إعدادات الغرفة مرة واحدة، وحالة كل مستخدم وصلاحياته ومواعيد الكتم وإصدارها في الذاكرة. المشرف المؤقت مصدره Node فقط. الرسائل وطلبات المايك تُفحص محليًا دون Laravel ودون انتظار طابور الغرفة. **لا يوجد فحص دوري للمشاركين كل دقيقة.**

## التحديثات الموثقة

يحفظ Laravel إشعارًا في `room_policy_events` داخل نفس معاملة الإعدادات أو العضوية المعتمدة أو العقوبات أو الأدوار الثابتة أو قفل الرسائل. بعد نجاح المعاملة يرسله إلى:

`POST /internal/socket/v1/rooms/{numericRoomId}/policy-refresh`

يوثّق بتوكن `SOCKET_INTERNAL_SERVICE_TOKEN`، ويحدد `SOCKET_NODE_BASE_URL` أصل Node الداخلي بلا مسار. الجسم يحتوي `version,room_id,livekit_room_name,suspended,settings,messages_locked,user`. الإصدار نص رقمي، و`suspended` قيمة منطقية مطلوبة، و`user` إما null لتغيير عام، أو حالة المستخدم المستهدف: `id,role,is_member,banned,banned_until,mic_muted,mic_muted_until,messages_muted,messages_muted_until`. التواريخ ISO بمنطقة زمنية. العقد الكامل ومثال JSON في [الدليل الإنجليزي](../en/room-controls.md).

يقارن Node إصدار إعدادات الغرفة وإصدار كل مستخدم بصورة مستقلة، ويتجاهل الأقدم والمكرر. إشعار أحدث لمستخدم لا يلغي تحديثًا صالحًا لمستخدم مختلف. استجابة `/policy` تضيف `data.snapshot` بنفس الجسم لربط قراءة الدخول بالتحديثات. نتيجة أمر الإشراف المحفوظ تضيف `policy` بنفس الإشعار، فلا يحتاج Node طلب تحديث آخر بعد حفظ الأمر.

الرد الجديد HTTP 200 مع `{success:true,roomId,version}` بعد تطبيق الحالة المحلية. تحديث LiveKit مستقل عن الرد. فشل التسليم أو غياب الإقرار الصحيح يبقي الإشعار لإعادة الإرسال. أمر `php artisan socket:deliver-room-policy` يعيد إرسال حتى 100 إشعار معلق في المرة، بفواصل إعادة محاولة من 5 إلى 300 ثانية. يشغله Laravel scheduler كل دقيقة؛ هذا يفحص إشعارات فاشلة فقط وليس المستخدمين. جدول الأحداث يحتفظ بالإصدارات المسلّمة أيضًا؛ لا تحذفه قبل وضع سياسة احتفاظ تحفظ أحدث إصدار.

## الإيقاف الإداري للغرفة

يقارن Node إصدارات الغرفة النصية باستخدام `BigInt`، ويحتفظ بآخر إصدار وحالة الإيقاف حتى بعد خروج آخر اتصال Socket، ويتجاهل التكرار والنسخ الأقدم. عند `suspended: true` يرفض الانضمام بـ`ROOM_SUSPENDED` دون استثناء المالك أو المشرف، ويلغي محاولات الانضمام المعلقة، ويفصل جميع sockets المسجلة للغرفة مع تسجيل انتقال `left` عبر الحضور. انضمام الضيوف إلى Socket غير مدعوم أصلًا.

يجدول Node أيضًا مسحًا لغرفة LiveKit: يستدعي `listParticipants` ثم يحاول إزالة كل هوية يعيدها دون استثناء المشاركين ذوي `hidden=true`، بما فيهم `admin-listen:{uuid}` والمشارك الذي لا يملك اتصال Socket. لا يصدر عن هذا المسح أحداث مستخدمين أو حضور أو زيارات لهويات LiveKit فقط. نجاح HTTP 200 من `policy-refresh` يعني قبول الحالة المحلية وجدولة مهمة LiveKit فقط، ولا يثبت اكتمال الإزالة. تعاد محاولة الإزالة الفاشلة عبر طابور الوسائط الحالي، لكن مهامه داخل ذاكرة Node وتضيع عند إعادة التشغيل.

عند `suspended: false` يرفع Node الإيقاف العام فقط؛ لا يعيد إدخال أي مشارك ولا يلغي حظرًا أو كتمًا أو قيد عضوية مستقلًا. طلب الدخول الجديد يقرأ سياسة Laravel الحالية. قد يعيد توكن LiveKit صالح صادر قبل الإيقاف الاتصال حتى انتهاء صلاحيته ما لم يمنعه webhook أو مسار دخول موثوق في خادم LiveKit الفعلي. يجب التحقق من سلوك `listParticipants` مع المشاركين المخفيين على نسخة الخادم الإنتاجية قبل تفعيل `LIVEKIT_ADMIN_LISTENING_VERIFIED`. مستمع الإدارة بهوية `admin-listen:{uuid}` يظل مشارك LiveKit فقط، ولا يُضاف إلى قوائم أو حضور Socket.

## سلوك الغرفة والعميل

- `roomPolicyUpdated` يرسل للاتصالات المعنية `{roomId,settings,permissions}`. تستمر أحداث المايك والأدوار القديمة، ويعرض الترحيب والقوانين كنص عادي.
- الرسالة نص غير فارغ بحد تقني 10,000 محرف Unicode. يطبق Node محليًا المنع والطول والروابط والكتم والفاصل واستثناءات المشرفين. رفض الرسالة `messageRejected` يعيد `code,message` و`retry_after` بالثواني عند الحاجة. منع الروابط يغطي الأشكال المعتادة فقط. الفاصل مشترك بين اتصالات المستخدم في الغرفة داخل العملية، ويظل فعالًا عند إعادة الاتصال الفورية حتى ينتهي. لا يستخدم Node واجهة `authorize-message` لكل رسالة بعد الآن؛ تبقى الواجهة متاحة في Laravel لبقية المستهلكين.
- جعل الغرفة للأعضاء فقط يقيّد الدخول الجديد؛ الزوار الموجودون لا يطردون ولا تفقد رسائلهم والمايك لمجرد تغيير شرط العضوية. تبقى قيود الرسائل والمايك الأخرى فعالة.
- الحظر يرسل `kicked` قبل الفصل، ويزيل عضوية Socket ويسجل خروج `ban`، ويجدول إزالة LiveKit مستقلًا. الحظر المؤقت لا يحتاج مؤقت فك حظر في Node بعد الفصل؛ يتحقق Laravel عند محاولة العودة.
- الكتم المؤقت فقط يجدول تحديث المستخدم المتصل عند موعد الانتهاء دون طلب Laravel. مغادرة آخر اتصال للمشرف المؤقت تسحب امتيازه من LiveKit من الحالة المحفوظة.

## أداء LiveKit والتشغيل

تحديثات صلاحيات الصوت والبيانات تُنفذ فقط عند تغير الصلاحية، بحد أقصى 8 عمليات متزامنة، مع دمج التحديثات لنفس المشارك وإعادة محاولة الفاشل فقط. لا تحجز طابور رسائل الغرفة أو أوامرها أثناء انتظار LiveKit. تحديث الصلاحيات يقرأ مشاركًا واحدًا ويحافظ على hidden وrecorder؛ أما الإيقاف فيسرد جميع هويات الغرفة ويزيلها.

يلزم قبل التشغيل:

1. تطبيق migration الجديدة `2026_11_15_000006_create_room_policy_events_table.php` بعد migrations التحكم السابقة. لم تُشغّل على قاعدة البيانات الفعلية أثناء التطوير.
2. ضبط `SOCKET_NODE_BASE_URL` وتوكنات الخدمة وتشغيل Laravel scheduler عبر `php artisan schedule:work` أو cron الخاص بـ`php artisan schedule:run`. ترك الأصل فارغًا يبقي الإشعارات معلقة. يمكن إعادة التسليم يدويًا عبر `php artisan socket:deliver-room-policy`.
3. نشر المشروعين معًا؛ Node يحتاج snapshot الجديدة، وعقد الجسم الفارغ ورد 202 القديم استُبدل بجسم ذي إصدار ورد 200.
4. اختبار تكامل حي وحمل فعلي. هذا التغيير ليس إثباتًا لتحمل مليون اتصال.

الحدود الحالية: حالة الغرفة وإصداراتها والفاصل الزمني محلية لعملية Node؛ تعدد الخوادم يحتاج حالة مشتركة وإيصال التحديث لكل مالك غرفة. مهام LiveKit وإعادة محاولتها لا تبقى بعد إعادة تشغيل العملية. مدة التوكن الجديد 600 ثانية، والتوكنات السابقة لا تُلغى وقد يقبلها الخادم الذاتي حتى انتهائها. المستودع يثبت إصدار SDK `livekit-server-sdk` فقط ولا يحدد إصدار LiveKit Server المنشور. قبل التفعيل يجب التحقق على الخادم الفعلي من إصدار LiveKit، وظهور المشاركين المخفيين في `listParticipants`، وسياسة webhook/الدخول، وانتهاء التوكنات القديمة. لا توجد heartbeat لإغلاق الزيارات بعد انهيار Node. دخول ضيوف Socket غير مدعوم.

صاحب الغرفة والمشرف الدائم والمشرف المؤقت الموثق مستثنون من حد طول الرسالة الخاص بالغرفة والفاصل الزمني ومنع الرسائل الجماعي وروابط الزوار. يبقى الحد العام 10,000 محرف مطبقًا.
