# تكامل التحكم بالغرف

الدخول للمسجلين فقط: JWT موثق ثم نجاح `authorize-join`، ثم قراءة `/policy` ورفض الدخول عند وجود `permissions.entry_error` حتى مع HTTP 200. هوية العميل ودوره لا يؤخذان من الحمولة، والمشرف المؤقت مصدره حالة Node الموثوقة.

`sendMessage` يقبل نصًا غير فارغ بحد تقني 10,000 محرف. يُستدعى `/authorize-message` قبل كل بث، ولا يصدر `newMessage` إلا عند `allowed: true` المنطقية. حدث `messageRejected` يحتفظ بكود Laravel، ويضيف `retry_after` بالثواني عند الفاصل الزمني. تعطل Laravel يمنع البث، ولا تعاد الرسالة تلقائيًا لأن التحقق الناجح يحجز الفاصل.

حدث خاص جديد `roomPolicyUpdated` يعيد `{roomId, settings, permissions}` عند الدخول وعند تغير السياسة الفعلية. تتضمن الصلاحيات `entry_error, role, can_publish, can_message, direct_data_allowed` وباقي حقول العضوية والروابط والطول والفاصل. يعرض الترحيب والقوانين كنص عادي. يستمر دعم أحداث المايك القديمة، ويفحص `requestMic` سياسة Laravel قبل حجز المقعد.

الحظر يزيل عضوية Socket ويفصل الاتصال ويزيل مشارك LiveKit ويسجل سبب الخروج `ban`. زيارات المسجلين تستمر عبر `presence` مع أسباب الخروج والمغادرة والانقطاع والطرد والحظر. قفل العضوية لا يطرد الزوار الموجودين تلقائيًا؛ صلاحيات المايك والرسائل الفعلية تبقى من Laravel.

## المزامنة والأداء

اضبط `SOCKET_NODE_BASE_URL` في Laravel على أصل خادم Node الداخلي. بعد نجاح المعاملة يرسل Laravel طلبًا إلى:

`POST /internal/socket/v1/rooms/{numericRoomId}/policy-refresh`

الجسم `{}` والتوثيق `Authorization: Bearer <SOCKET_INTERNAL_SERVICE_TOKEN>`. لا يقبل المسار هوية أو دورًا أو صلاحيات من العميل. الرد 202 إقرار بجدولة التحديث وليس ضمان نجاح LiveKit. الإقرار السريع يمنع التعارض عندما ينتظر Node نتيجة أمر Laravel؛ تنتهي محاولة الإشعار خلال ثانيتين ولا تتراجع البيانات المحفوظة عند فشلها.

يشمل الإشعار الإعدادات والعضوية المعتمدة والعقوبات والأدوار الثابتة وقفل الرسائل. يقرأ Node سياسات المشاركين الحاليين ويحدث `canPublish` و`canPublishData` مع الحفاظ على بقية صلاحيات LiveKit، ومنها الإخفاء. الحقل الإضافي `data.next_change_at` في السياسة يحدد موعد إعادة الفحص عند انتهاء العقوبة. فحص احتياطي كل دقيقة يعالج الإشعارات المفقودة والأخطاء دون تداخل الدورات. لا يرسل تحديثًا للعميل إذا لم تتغير السياسة. إزالة صلاحية المشرف المؤقت عند مغادرة آخر اتصال تحدث LiveKit أيضًا. يعاد فصل LiveKit الفاشل للحظر بعد التأكد أن الحظر ما زال فعالًا.

## قبل الإنتاج

- انشر التكامل في المشروعين واضبط أصل Node وتوكن الخدمة، واستخدم cache ذرية مشتركة في Laravel للفاصل الزمني.
- اختبر على LiveKit الحقيقي: رفض الدخول والرسائل ومدة الانتظار وتغيير REST والعضويات والعقوبات والأدوار وانتهائها وتعدد الاتصالات وسحب صلاحيات الصوت والبيانات.
- توكنات LiveKit الجديدة مدتها 600 ثانية؛ القديمة لا تتغير. على LiveKit المستضاف ذاتيًا لا يلغي الفصل أو تحديث الصلاحية التوكن القديم. أوقف إصدار الصلاحيات القديمة ونسّق فصل المشاركين وإعادة دخولهم وانتظر أطول مدة للتوكنات السابقة (الافتراضي السابق ساعة)، أو اعتمد خطة منفصلة لإبطال مفاتيح الخادم. قصر المدة وحده لا يحقق الإلغاء الفوري.
- المزامنة تخص المشاركين المتصلين بـSocket، مع تنظيف دور المشرف المؤقت عند مغادرته. دخول LiveKit وحده أو إعادة استخدام توكن قديم دون Socket يحتاج webhook موثقًا لدخول المشاركين قبل اعتبار القيود لحظية على جميع العملاء.
- حالة الغرف والأدوار المؤقتة ومحاولات فصل LiveKit والمؤقتات محلية للعملية. عند تعدد خوادم Node يجب إرسال الإشعار لكل خادم؛ موازن حمل يختار خادمًا واحدًا لا يكفي. راقب أخطاء المزامنة؛ قد يزيد التأخير عن دقيقة عند التعطل أو كثرة المشاركين. لا توجد heartbeat لإغلاق الزيارات بعد انهيار Node.

دخول الضيوف المجهولين يبقى معطلًا حسب الاتفاق. تفعيله لاحقًا يحتاج عقد دخول وهوية ثابتة من الخادم متطابقة مع LiveKit، ثم `guest-visits` بمعرف زيارة UUID ثابت ووقت الدخول الأصلي عند الخروج وإعادة الإرسال. لا يرسل المسجل إلى مساري الزيارات معًا.

دخول مدير المنصة متخفيًا لم يضف بعد لغياب عقد موثوق. نحافظ على صلاحية `hidden` الموجودة في LiveKit، ولا نقبل حقلًا من العميل يمنحها. الدور الموثوق والاستماع فقط والتدقيق الخاص واستبعاده من قوائم الغرفة والعداد والزيارات تحتاج عقدًا مستقلًا لاحقًا.
